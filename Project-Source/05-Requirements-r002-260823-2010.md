# 05 — Requirements

### REQ-001 — Locally pinned Project Source
- **Status:** ACTIVE
- **Requirement:** Maintain a valid active `FRAMEWORK-001` and mandatory Project Source documents pinned to Framework `1.3.0` / Schema `1.0.0` until an explicitly approved upgrade occurs.
- **Acceptance / Verification Criteria:** Root exists in slot `00`; mandatory documents exist; inheritance/version metadata is coherent; no auto-upgrade.
- **Priority / Scope:** HIGH / Project governance
- **Epistemic Status:** USER_CONFIRMED
- **Related:** DEC-001; ACT-001; EVD-001

### REQ-002 — Deterministic local/repository routing
- **Status:** ACTIVE
- **Requirement:** Material local/Git work must resolve active `FRAMEWORK-001` location binding and fresh dynamic Git state before mutation.
- **Acceptance / Verification Criteria:** GitHub + local workspace bindings match intended target; mismatch fails closed; current branch/worktree is freshly observed when material.
- **Priority / Scope:** HIGH / Repository and local execution
- **Epistemic Status:** USER_CONFIRMED
- **Related:** DEC-002; EVD-002

### REQ-003 — Secret isolation
- **Status:** ACTIVE
- **Requirement:** Project Source stores secret references/metadata only; actual credentials, API keys, passwords and secret-bearing URLs remain outside Project Source and Git.
- **Acceptance / Verification Criteria:** `17` contains no secret value; `secret_value_present: false`; no Project Source binding contains credentials.
- **Priority / Scope:** HIGH / Security
- **Epistemic Status:** VERIFIED

### REQ-004 — Preserve pre-existing implementation WIP
- **Status:** ACTIVE
- **Requirement:** Project governance work must not reset, overwrite, clean, or accidentally include pre-existing source changes in a governance completion commit.
- **Acceptance / Verification Criteria:** Governance commit is path-scoped to `Project-Source/`; pre-existing tracked/untracked implementation changes remain present and separately identifiable.
- **Priority / Scope:** HIGH / Governance safety
- **Epistemic Status:** USER_CONFIRMED
- **Related:** ACT-001; RISK-001; EVD-003; ISS-002

### REQ-005 — Out-of-Band Recoverability
- **Status:** ACTIVE
- **Requirement:** lnwjud recovery must provide a path to inspect, start, stop, restart, diagnose, and verify the lnwjud execution stack without depending exclusively on lnwjud/MCP itself.
- **Acceptance / Verification Criteria:** A governed recovery design covers machine reachability, engine/server/tunnel state, tool discovery and a test command; escalating recovery levels preserve authorization boundaries and destructive actions require explicit authority.
- **Priority / Scope:** HIGH / Recovery and resilience
- **Epistemic Status:** USER_CONFIRMED
- **Related:** ACT-LNW-001; REQ-010

### REQ-006 — Rolling Upstream Customization Continuity
- **Status:** ACTIVE
- **Requirement:** Upstream application updates must be consumable without silently losing intentional lnwjud customization; upstream-oriented baseline and controlled customization work must remain distinguishable.
- **Acceptance / Verification Criteria:** Upgrade work freshly observes Git state, compares prior upstream/custom intent to new upstream, drops obsolete/upstream-resolved patches, forward-ports still-valid intent, runs affected regression, and preserves a rollback path before stable promotion.
- **Priority / Scope:** HIGH / Application upgrade and source control
- **Epistemic Status:** USER_CONFIRMED
- **Related:** ACT-LNW-002; REQ-002; ISS-002

### REQ-007 — Durable Task Identity and Continuity
- **Status:** ACTIVE
- **Requirement:** A Project task identity must not depend on a single GPT chat/session, Codex run, or lnwjud process lifetime; sufficient governed state must persist for reliable continuation.
- **Acceptance / Verification Criteria:** Task identity, status, resumable context, journal/checkpoints and artifact references survive expected session/runtime restart according to the declared persistence authority.
- **Priority / Scope:** HIGH / Persistent task bridge
- **Epistemic Status:** USER_CONFIRMED
- **Related:** ACT-LNW-003

### REQ-008 — Verified Resume and Concurrency Protection
- **Status:** ACTIVE
- **Requirement:** Durable task resume must reconcile persisted state with actual machine/Git state before execution, and concurrent agents must not mutate the same governed task without ownership/lease protection; approval state must remain explicit.
- **Acceptance / Verification Criteria:** Resume performs actual-vs-stored reconciliation, stale state does not override current machine/Git truth, lease/ownership prevents uncontrolled concurrent mutation, and required approvals are persisted/revalidated rather than inferred.
- **Priority / Scope:** HIGH / Task correctness and concurrency
- **Epistemic Status:** USER_CONFIRMED
- **Related:** ACT-LNW-003; REQ-002

### REQ-009 — Independent Remote Control and Recovery Plane
- **Status:** ACTIVE
- **Requirement:** Remote status/control/recovery must have a supervisor/control path that can remain reachable independently of the lnwjud execution plane when lnwjud itself is offline or unhealthy.
- **Acceptance / Verification Criteria:** Design separates Web/remote control, supervisor/recovery, lnwjud execution and task-persistence responsibilities; supervisor status can distinguish machine reachability from lnwjud health and supports bounded recovery actions.
- **Priority / Scope:** HIGH / Remote operations and resilience
- **Epistemic Status:** USER_CONFIRMED
- **Related:** ACT-LNW-004; REQ-005

### REQ-010 — Secure and Governed Remote Operations
- **Status:** ACTIVE
- **Requirement:** Remote connectivity and recovery actions must use an authenticated secure control model with authorization/audit boundaries; destructive or system-wide actions must not be auto-authorized by connectivity alone.
- **Acceptance / Verification Criteria:** Proposed control channel is outbound-secure or equivalently bounded, action classes distinguish normal/diagnostic/recovery/high-risk operations, and high-risk/destructive actions require explicit governed approval with auditable evidence.
- **Priority / Scope:** HIGH / Security and remote authority
- **Epistemic Status:** USER_CONFIRMED
- **Related:** ACT-LNW-001; ACT-LNW-004; REQ-003
